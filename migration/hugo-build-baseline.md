# Hugo Build Baseline (Parity Reference)

This repo already contains enough information to rebuild the same site in Next.js, but the most reliable “source of truth” for styling and layout parity is the built output under `public/`.

## Build + Serve

- Build (production-ish):
  - `hugo --minify`
  - Output: `public/`
- Serve `public/` for inspection:
  - `python3 -m http.server 4173` (run inside `public/`)
  - URL: `http://localhost:4173/`

## Key Routes (from `public/**/*.html`)

- `/` (home with anchored sections)
- `/posts/` (list)
- `/posts/<slug>/` (detail)
- `/portfolios/` (list)
- `/portfolios/<slug>/` (detail)
- `/categories/`, `/tags/`
- `/404.html`

## What Defines “Identical”

Use the Hugo build output as the baseline, then compare the Next.js build against these:

- Layout: navbar, spacing, typography scale, section alignment, cards, sidebar behavior.
- Visual: colors, background image behavior across breakpoints, iconography, hover states.
- Content: all strings match (including HTML in About summary), links, ordering, and dates.
- Responsive: verify at least one mobile-ish width and one desktop width.

## Built HTML Notes (Important for Next Parity)

From the built home page HTML (`public/index.html`):

- Home background uses inline `<style>` that swaps background images via media queries and uses the production `baseURL`:
  - `background-image:url(https://kangfarih.github.io/images/star-background_*.jpg)`
- Many images are generated by Hugo image processing and emitted with hashed filenames:
  - Example: `/images/site/wind_hu_eb4f864b51fe454a.png`

In Next.js, expect to replicate this either by:

- Porting the already-generated images from `public/images/**`, or
- Rebuilding a similar responsive-image pipeline (Next Image + multiple sizes) and matching breakpoints.
